## Project overview

Static HTML website for **Duurkracht Kozijnen B.V.** — a Dutch specialist in kunststof (plastic) window frames, doors, sliding doors, and Keralit cladding, based in Hengelo (Overijssel). Deployed on Vercel. No build toolchain; pages are pure HTML/CSS/JS or generated by Python scripts.

## Local development

Serve the site locally with any of:

```bash
python3 -m http.server 8000          # built-in, zero dependencies
npx --yes serve . -l 3000            # Node serve
npx --yes http-server . -p 8080 -c-1 # Node http-server, no cache
```

Deploy to production:

```bash
vercel deploy --prod --yes
```

## Page generation — Python build scripts

Most page types are generated from a single Python source file. **Always edit the generator, then regenerate; never hand-edit the generated HTML for these page types.**

| Script | Generates | Command |
|---|---|---|
| `build_location_pages.py` | `/kunststof-kozijnen-{slug}/index.html` (20 city pages) | `python3 build_location_pages.py` |
| `build_blog.py` | `/blog/index.html` + `/blog/{slug}/index.html` | `python3 build_blog.py` |
| `build_service_pages.py` | `/diensten/*/index.html` + `/diensten/index.html` | `python3 build_service_pages.py` |
| `build_picture_tags.py` | Upgrades `<img>` to `<picture>` with WebP source across all HTML | `python3 build_picture_tags.py` |

`build_picture_tags.py` is idempotent — safe to re-run after adding new images. Images in `design-assets/images/` should have both `.jpg` and `.webp` versions.

## Architecture

### Static files vs. generated files

- **Hand-maintained HTML**: `index.html`, `contact/index.html`, `over-ons/index.html`, `projecten/index.html`, `faq/index.html`, `kosten/index.html`, `eigenaren/index.html`, `configurator/index.html`, `privacybeleid/index.html`
- **Generated HTML**: everything under `diensten/*/`, `blog/*/`, and `kunststof-kozijnen-*/`
- **Compatibility shims**: `diensten/*.html` and `blog/kosten-kunststof-kozijnen.html` — lightweight redirect pages for old `.html` URLs; do not delete unless explicitly asked to remove old URL compatibility

### CSS & JS

- `css/site.css` — shared stylesheet for all pages (CSS custom properties for brand colours, typography, layout)
- `css/style.css` — legacy file; `site.css` is preferred for new work
- `js/main.js` — minimal JS; page-specific scripts are inlined in the HTML

### Routing & redirects

`vercel.json` manages:
- `cleanUrls: true` and `trailingSlash: false`
- Permanent redirects for old `/locaties/*` and `/nieuws/*` (WordPress legacy) paths
- Permanent redirects for renamed service slugs (e.g. `/diensten/schuifpuien` → `/diensten/kunststof-schuifpuien`)
- Cache headers: images immutable (1 year), CSS/JS 24 h, security headers on all routes
- `preview`, `index-original` are marked `noindex`

### SEO infrastructure

- `sitemap.xml` — must be updated manually when pages are added
- `robots.txt` — 18 AI crawlers explicitly allowed
- `llms.txt` — verified facts for AI tools (keep in sync with actual specs if specs change)
- Every page includes JSON-LD structured data (LocalBusiness, FAQ, Article, etc.) and canonical URL
- All images must have `alt` attributes; all local image paths must exist

## Content conventions

**Lead with homeowner outcomes, not technical specs.** The communication hierarchy:
1. Hero / cards / FAQs: warmer home, less draft, less noise, less maintenance, neat installation, clear planning
2. Proof sections: technical specs (Schüco LivIng 82, Uf 0.92, RC2, stelkozijn-montage)

Keep these facts consistent across all pages:
- Product line: **Schüco LivIng 82** exclusively (not generic "A-merk")
- Montage method: **kunststof stelkozijn** (not concrete or plaster anchoring)
- Warranty: **10 jaar** on profile and installation
- Throughput: **6–8 weken** (vs sector average 12–16 weeks)
- Rating: **4,9 / 5** on Google Reviews
- Company: Hassinkweg 1, 7556 BV Hengelo · KvK 90895312 · 085 073 1660
